# 用户和管理员登录功能实现计划

## 1. Summary

为运动姿态评估系统添加完整的用户和管理员登录功能：

* 后端使用 SQLite 数据库持久化用户表，支持普通用户(user)和管理员(admin)两种角色。

* 使用 JWT Token 进行无状态认证，登录后前端每次请求携带 token。

* 支持用户注册、登录、获取当前用户信息。

* 前端新增登录页，未登录时跳转到登录页；登录后显示主界面并根据角色展示不同内容。

* 普通用户进入"学生训练端"，管理员进入"管理后台"并可访问动作规则配置。

## 2. Current State Analysis

### 2.1 后端现状

* **框架**: FastAPI + SQLAlchemy + Pydantic v2

* **数据库**: `backend/app/core/config.py` 默认配置为 `mysql+pymysql://pose:pose@mysql:3306/pose_evaluation`，但项目文档说明首期使用内存服务，已有 SQLAlchemy session 配置 (`backend/app/db/session.py`)。

* **依赖**: 当前 `requirements.txt` 没有 JWT 和密码哈希库，需要新增 `python-jose[cryptography]` 和 `passlib[bcrypt]`。

* **模型**: `backend/app/models/entities.py` 目前只有 dataclass 内存模型，需要新增 SQLAlchemy 用户模型，或统一改为 ORM 模型。

* **路由**: `backend/app/api/router.py` 统一注册所有路由，新增 `auth.py` 路由后在此注册。

* **会话服务**: `backend/app/services/session/session_service.py` 使用内存列表，后续训练记录需关联 `user_id`。

### 2.2 前端现状

* **框架**: Vue 3 + TypeScript + Pinia + Vue Router

* **入口**: `frontend/src/App.vue` 直接渲染主界面（带侧边栏），没有登录入口。

* **路由**: `frontend/src/router/index.ts` 只有 6 个页面路由，缺少登录路由和路由守卫。

* **状态管理**: `frontend/src/stores/training.ts` 管理训练状态，需新增 `auth.ts` 管理登录状态。

* **API 客户端**: `frontend/src/api/client.ts` 只有基础 GET/POST/Upload，需扩展 token 注入和 401 处理。

### 2.3 需要解决的问题

1. 当前 `config.py` 使用 MySQL，本地开发可能未安装 MySQL；为登录功能应先切换到 SQLite 或配置可选数据库。
2. `entities.py` 是 dataclass，不是 SQLAlchemy 模型；新增用户表需要引入 ORM 基类。
3. 前后端目前都没有认证拦截，需要逐步添加受保护路由。

## 3. Proposed Changes

### 3.1 后端变更

#### 3.1.1 依赖更新

**文件**: `backend/requirements.txt`

新增依赖：

```text
python-jose[cryptography]==3.3.0
passlib[bcrypt]==1.7.4
python-multipart==0.0.9  # 已存在，但 Form 登录需要
```

原因：JWT 签发/校验需要 `python-jose`，密码哈希需要 `passlib[bcrypt]`。

#### 3.1.2 数据库模型

**文件**: `backend/app/models/entities.py`

* 新增 SQLAlchemy Base 和 `User` 模型：

  * `id`: Integer 主键

  * `username`: String, unique, indexed

  * `hashed_password`: String

  * `role`: String (`user` 或 `admin`)

  * `is_active`: Boolean, 默认 True

  * `created_at`: DateTime

* 保留现有 dataclass 形式的数据结构不变（如 `User` dataclass），避免破坏其他模块引用；或在 SQLAlchemy 模型基础上保持兼容。

原因：实现用户持久化，区分角色。

#### 3.1.3 数据库会话与初始化

**文件**: `backend/app/db/session.py`

* 保留现有 engine/SessionLocal 逻辑。

**文件**: 新增 `backend/app/db/init_db.py`

* 调用 `Base.metadata.create_all(bind=engine)` 创建所有表。

* 提供 `init_db()` 函数，在应用启动时执行。

* 在初始化时检查是否存在管理员账号；不存在则创建默认管理员 `admin / admin123` 和默认普通用户 `user / user123`。

原因：首次启动自动建表并生成默认账号，方便演示。

#### 3.1.4 安全工具

**文件**: 新增 `backend/app/core/security.py`

实现以下函数：

* `verify_password(plain_password, hashed_password) -> bool`

* `get_password_hash(password) -> str`

* `create_access_token(data: dict, expires_delta: timedelta | None = None) -> str`

* `decode_access_token(token: str) -> dict`

原因：封装密码和 JWT 相关逻辑。

#### 3.1.5 认证依赖

**文件**: 新增 `backend/app/api/deps.py`

实现 FastAPI 依赖：

* `get_db() -> Session`

* `get_current_user(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)) -> User`

* `get_current_active_user(current_user: User = Depends(get_current_user)) -> User`

* `require_admin(current_user: User = Depends(get_current_active_user)) -> User`

原因：保护后续需要登录或管理员权限的接口。

#### 3.1.6 认证路由

**文件**: 新增 `backend/app/api/routes/auth.py`

实现接口：

* `POST /api/auth/register`

  * Body: `{ "username": "...", "password": "...", "role": "user" }`

  * 校验用户名唯一，密码长度 >= 6，角色只能是 `user` 或 `admin`。

  * 返回用户信息（不含密码）。

* `POST /api/auth/login`

  * Form: `username`, `password`

  * 校验账号密码，返回 `{ "access_token": "...", "token_type": "bearer", "user": {...} }`。

* `GET /api/auth/me`

  * 依赖 `get_current_active_user`

  * 返回当前登录用户信息。

原因：提供登录、注册、获取当前用户接口。

#### 3.1.7 路由注册

**文件**: `backend/app/api/router.py`

* 导入并注册 `auth.router`：

  ```python
  from app.api.routes import auth
  router.include_router(auth.router)
  ```

#### 3.1.8 应用启动初始化

**文件**: `backend/app/main.py`

* 在 `create_app()` 中调用 `init_db()` 创建表和默认账号。

#### 3.1.9 数据库配置调整（可选但建议）

**文件**: `backend/app/core/config.py`

* 将默认 `database_url` 改为 SQLite，便于本地开发：

  ```python
  database_url: str = os.getenv(
      "DATABASE_URL",
      "sqlite:///./pose_evaluation.db",
  )
  ```

* 保持通过环境变量可覆盖为 MySQL。

原因：降低本地运行门槛，登录功能需要数据库可立即使用。

#### 3.1.10 现有服务兼容

**文件**: `backend/app/services/session/session_service.py`

* 当前使用内存列表，创建训练记录时不关联用户。

* 本计划**暂不修改**训练记录模型，避免范围扩大；但预留 `user_id` 字段，后续扩展时传入即可。

### 3.2 前端变更

#### 3.2.1 状态管理

**文件**: 新增 `frontend/src/stores/auth.ts`

* 定义 `AuthState`：

  * `token: string | null`

  * `user: { id, username, role } | null`

  * `isAuthenticated: boolean`

Actions：

* `login(username, password)`：调用 `/api/auth/login`，保存 token 到 localStorage，设置 user。

* `register(username, password, role)`：调用 `/api/auth/register`。

* `fetchCurrentUser()`：调用 `/api/auth/me`。

### `logout()`：清除 token 和 user，跳转登录页。

初始化时从 `localStorage` 读取 token 并尝试获取当前用户。

原因：集中管理登录状态和 token。

#### 3.2.2 API 客户端增强

**文件**: `frontend/src/api/client.ts`

* 新增 `apiPostAuth`、`apiGetAuth`、`apiUploadAuth` 等函数，自动在 Header 中附加 `Authorization: Bearer ${token}`。

* 或者在底层 fetch 封装中统一读取 `useAuthStore().token`。

* 对 401 响应统一调用 `logout()` 并跳转登录页。

原因：所有受保护接口需要携带 token。

#### 3.2.3 登录页面

**文件**: 新增 `frontend/src/views/LoginView.vue`

* 提供登录表单：用户名、密码。

* 提供"去注册"切换和注册表单：用户名、密码、确认密码、角色选择（普通用户/管理员）。

* 调用 auth store 的 `login` / `register`。

* 登录成功后根据角色跳转：

  * `user` -> `/`

  * `admin` -> `/rules`（管理后台，可调整）

原因：提供登录入口。

#### 3.2.4 路由守卫

**文件**: `frontend/src/router/index.ts`

* 新增 `/login` 路由，指向 `LoginView`。

* 添加全局 `beforeEach` 守卫：

  * 读取 auth store 的 `isAuthenticated`。

  * 未登录且访问非登录页 -> 重定向到 `/login`。

  * 已登录且访问 `/login` -> 根据角色重定向到首页或管理页。

  * 普通用户访问需要管理员权限的页面 -> 重定向到首页。

原因：保护前端路由，区分角色访问。

#### 3.2.5 主界面调整

**文件**: `frontend/src/App.vue`

* 当前直接渲染主界面；修改后根据登录状态渲染：

  * 未登录：`<RouterView />`（显示登录页）

  * 已登录：保留现有 sidebar + topbar + content 布局

* 右上角显示当前用户名和角色，并提供"退出登录"按钮。

* 根据角色动态调整导航：

  * 普通用户：首页、实时检测、视频分析、训练记录、个人报告

  * 管理员：在普通用户基础上增加"动作规则"，或在顶部增加"管理后台"标识

原因：根据登录状态动态展示界面。

#### 3.2.6 角色相关 UI 调整

**文件**: `frontend/src/views/ExerciseRulesView.vue`

* 该页面涉及动作规则配置，建议仅对管理员完全开放编辑功能。

* 普通用户可以查看，但不能上传标准动作模板；管理员可以上传和编辑。

* （可选）在 plan 中仅简单隐藏"添加标准动作"按钮给普通用户，后续再细化权限。

原因：体现管理员与普通用户的区别。

## 4. Assumptions & Decisions

1. **数据库使用 SQLite 作为默认**：降低本地开发门槛；生产可通过环境变量切换回 MySQL。
2. **JWT 使用 HS256 算法**，secret key 从环境变量读取，默认值为一个固定字符串（仅开发环境）。
3. **默认预置账号**：管理员 `admin / admin123`，普通用户 `user / user123`。
4. **角色仅两种**：`user` 和 `admin`。
5. **Token 过期时间**：默认 7 天，可在 `config.py` 中配置。
6. **训练记录暂不关联 user\_id**：本次登录功能先完成认证体系，训练记录关联用户在后续迭代中实现。
7. **前端状态持久化**：token 保存在 `localStorage`，刷新页面后保持登录状态。
8. **密码策略**：最小长度 6 位，不强制复杂度，避免过度工程。
9. **注册功能允许选择角色**：为了演示管理员和普通用户两种登录路径；实际产品应限制普通用户只能注册 `user` 角色。

## 5. Verification Steps

### 5.1 后端验证

1. 安装新增依赖：`pip install -r backend/requirements.txt`
2. 启动后端：`uvicorn app.main:app --reload`
3. 检查数据库文件 `pose_evaluation.db` 已创建，且包含 `users` 表。
4. 调用 `POST /api/auth/login`：

   * `username=admin&password=admin123` 应返回 token 和 `role=admin`

   * `username=user&password=user123` 应返回 token 和 `role=user`

   * 错误密码应返回 401
5. 调用 `GET /api/auth/me` 携带正确 token，返回当前用户信息。
6. 调用 `POST /api/auth/register` 注册新用户，然后登录验证。

### 5.2 前端验证

1. 进入首页 `/`，未登录时自动跳转到 `/login`。
2. 使用 `user / user123` 登录，显示"学生训练端"，侧边栏无"动作规则"。
3. 退出后使用 `admin / admin123` 登录，显示"管理后台"，侧边栏有"动作规则"。
4. 普通用户直接访问 `/rules` 被重定向到首页。
5. 刷新页面后仍保持登录状态。
6. 调用需要认证的接口（如 `/api/auth/me`）能成功返回数据。

### 5.3 回归验证

1. 原有页面（实时检测、视频分析、训练记录等）在登录后仍能正常访问。
2. 模板生成和评分功能在管理员登录后仍可正常使用。
3. 运行 `python -m unittest discover -s backend/tests -p "test_*.py"` 确保现有测试通过。
4. 运行 `cd frontend && npm run build` 确保前端 TypeScript 检查通过。
